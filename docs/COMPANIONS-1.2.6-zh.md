# 随从与整理：1.2.6

> 这是 1.2.6 的历史说明。1.2.7 改为随从亲自走动整理、无需登记容器，请以 [1.2.7 指南](COMPANIONS-1.2.7-zh.md) 为准。

适用于 Minecraft 26.1.2、NeoForge 26.1.2.122、Java 25。客户端和服务端都需更新至 1.2.6，网络协议为 16。[English](COMPANIONS-1.2.6.md)。

本版新增随从指令“整理”，调整 Modern 模型的 UV 提交方式和 Beast 四足冲刺。已有祭坛、商人、招募、背包、狩猎、升级与复活规则继续使用；基础规则见 [1.2.4 指南](COMPANIONS-1.2.4-zh.md)，入口、私有对白及自定义称呼以 [1.2.5 指南](COMPANIONS-1.2.5-zh.md)和本页为准。旧指南中的 L 按键已改为默认 C；已保存的旧绑定需在控制设置中修改或恢复默认。

## 开始整理

1. 按随从管理键（默认 C），或右键自己的随从，选择“整理”。靠近随从后点击“登记容器”。
2. 首次登记以随从的位置为工作点。潜行右键原版箱子、陷阱箱或木桶，将其加入允许整理的名单；再次点击同一容器即可移除。
3. 打开随从管理结束登记。登记也会在五分钟后结束。回到整理页检查名单、工作点和整理方式，再点击“开始整理”。
4. 随从留在工作区，持续检查名单内的容器。可以在整理页停止，或切换跟随、守护、休息、狩猎、召回等指令结束当前工作。

整理使用已有随从及招募资格，没有额外的技能树加点、消耗或产出倍率。名称统一为“整理”。

## 范围和两种方式

工作区为工作点向东西南北各八格、上下各四格。每位随从最多登记二十四个逻辑容器；双箱计作一个，两半均需位于范围内并可访问。只登记允许自动搬动物品的储存容器；不会扫描邻近但未登记的箱子。

| 方式 | 行为 |
|---|---|
| 同类集中（默认） | 优先把同一种资源集中到本来存放它最多的已登记容器，使用该容器的可用空格；放不下的部分继续保留在其他容器。 |
| 仅合并堆叠 | 只填满已有的零散堆叠，不占用空格，不重新排列整个箱子。 |

例如，两堆各 32 个铁锭可合成一堆 64；两堆各 48 个圆石可合成 64 和 32。末影珍珠仍受每组 16 的上限约束。已满的堆叠不会被继续塞入物品，不能堆叠的装备保持原样。整理按轮次逐步收拢；某种物品本轮腾出的空格，可能由其他物品在下一轮使用，不保证一次扫描就达到最优布局。

“相同”要求物品类型和全部数据组件相同，不仅比较 ID。名称、耐久、附魔、药水、书本或容器内容不同的物品不会混合。整理不使用随从的九格背包中转，不把放不下的物品扔到地面。

“重设整理区”会停止整理、清空登记并把工作点移至随从当前位置，不修改任何箱中物品。整理页支持滚轮查看超过八项的名单；设置操作需在同维度靠近随从，停止整理可从总控发出。

## 多人、暂停和访问限制

名单与随从档案绑定主人 UUID，只有主人能调整和启动工作；指令反馈及整理对白也只发给主人。登记是玩家逐个选择容器的操作，不把“邻近”当成“有权访问”。

- 跳过已打开、被阻挡、上锁、受交互保护、尚未打开生成战利品或区块未加载的容器。双箱两半都需通过检查。
- 每次实际搬运前重新检查源和目标，避免玩家、漏斗、箱子拆除/替换或区块卸载使旧计划失效；不以旧快照覆盖整个箱子。
- 主人离线、离开该维度或随从离开工作区时暂停；恢复后根据实际物品重新规划。随从死亡、狩猎、召回或更换工作模式均不继续执行旧计划。
- 不强制加载区块，不跨维度读取容器。第一版只支持原版普通箱、陷阱箱和木桶，不自动整理熔炉、漏斗、末影箱或其他模组储存。

保护检查包括原版访问/出生点限制，以及 NeoForge 右键交互事件的取消或拒绝结果。领地模组有自己的权限模型；其是否通过此事件拦截访问，需与该模组组合验证，不承诺覆盖所有领地插件。

## 服务器配置

在 `config/howlingwerewolf-common.toml` 中：

```toml
[gameplay]
enableCompanions = true
enableCompanionSorting = true
```

`enableCompanionSorting` 默认 `true`。设为 `false` 只停止整理和相关设置，保留登记名单、箱子物品和其他随从功能。总开关 `enableCompanions = false` 仍会关闭全部随从操作，并按原有规则暂停狩猎和冷却。多人使用服务器配置。

## 算法与来源

实现采用“读取槽位、按完整资源分组、计算稳定目标、分批转移”的流程。分组键为 NeoForge `ItemResource`，数量不计入物品身份；哈希加速分组，完整相等性负责最终判断。同等目标按固定坐标及槽号排序，避免物品在箱子间反复移动。每位随从每刻最多执行四次转移，服务器每刻总上限十六次，且全服每刻最多执行两次完整扫描与规划；空闲后定期重新检查。

每次转移都在 NeoForge `Transaction` 中执行源抽取和目标插入，数量不匹配则回滚该次。已经完成的转移保留，失效部分重新规划。事务处理游戏运行中的一致性，不等同于对断电、磁盘损坏或所有外部模组错误作数据恢复保证。[NeoForge 事务说明](https://docs.neoforged.net/docs/inventories/transactions/)。

算法调研参考 [Inventory Sorter 的分组整理](https://github.com/cpw/inventorysorter/blob/main/src/main/java/cpw/mods/inventorysorter/SortingHandler.java)及[完整物品组件相等性](https://github.com/cpw/inventorysorter/blob/main/src/main/java/cpw/mods/inventorysorter/ItemStackHolder.java)这一常见思路。当前服务端白名单、计划与事务转移代码独立实现，不依赖或打包该项目；其 GPL 源码未复制到本模组。旧 [箱子整理草案](DRAFT-COMPANION-CHEST-SORTING.md)保留为历史提案，以本页实际行为为准。

## Modern 模型和 Beast 冲刺

Modern 模型的几何尺寸与 UV 尺寸可能不同。旧实现构造原版 Cube 后再改 UV；部分渲染优化会提前缓存构造参数。现在由导入模型直接提交最终面顶点、UV、颜色、光照和法线，避免使用修改前的缓存，覆盖三个 Modern 形态、分段护甲及使用这些模型的渲染入口。

Modern Beast 四足冲刺改为两条前肢成对先迈，后肢对随后跟进，包含摆腿抬爪、落地支撑及轻微身体起伏，保留站立、下蹲、游泳、持物等状态的独立处理。

兼容验证使用与本游戏版本匹配的 [Sodium 0.9.2 NeoForge 26.1.2](https://modrinth.com/mod/sodium/version/mc26.1.2-0.9.2-neoforge)。[Xenon 官方文件页](https://www.curseforge.com/minecraft/mc-mods/xenon/files/all)当前列出的是 1.20.1，不能把该版本的运行结果当成 26.1.2 的兼容结论。

## 验证范围

构建和 1323 项成品检查通过；原生 NeoForge 服务端 455 项检查通过，包含真实保存重启、双箱、权限撤销、事务回滚、120 组随机守恒与收敛及预算限制。模型/NPC/UI 回归通过 21129 项（包含独立 UI 检查的 368 项）。在指定游戏实例、NeoForge 26.1.2.122、RTX 4060 Laptop GPU 上，用普通渲染及 Sodium 0.9.2 各采集 16 组 GPU 画面：三形态九套毛色和钻石护甲的静态画面逐像素一致；八组四角度奔跑画面的最大偏差为 47 个前景像素，低于 0.08%，未出现 UV 错位。已另行复现 1.2.5 在 Sodium 下的原问题。最终 JAR 的全部 74 个客户端类与该 GPU 候选构建逐字节一致。未据此验证其他优化模组、着色器、所有领地组合或双真实客户端联机。
